# 第二階段追加驗收：自動日報生成配方

這份驗收只涵蓋每天排程生成的十篇日報。手動「再手沖一批」與歷史模擬不會被標成自動日報配方。

## 驗收結果

- [x] **每次生成都有獨立履歷。** 模型呼叫前先建立 UUID 與 `pending` 紀錄，最後更新為 `complete` 或 `failed`。
- [x] **日報保存不可變快照。** 每份自動 edition 嵌入 `generation_recipe`，包含當時的偏好、完整基礎 Prompt、Prompt 版本、模型與搜尋規則。
- [x] **每次模型嘗試都有實際 Prompt。** `generation_run.attempts` 保存每次重試真正送出的 system/user Prompt、模型與開始時間。
- [x] **日報和生成流程永遠相連。** edition 保存 `generation_run_id`，獨立 run 檔保存 `edition_id`、十篇標題與來源 URL。
- [x] **失敗也留得下來。** Windows 排程腳本會提交並推送失敗 run，不會只留下成功結果。
- [x] **過往日報可查看配方。** 今日手沖與過往手沖在 `has_recipe=true` 時顯示「查看本期配方」。
- [x] **可以安全複製與分享。** 公開 API 與配方視窗會移除 API Key、帳號 ID、排除主題及私人指定來源，只允許 `automatic_daily_brew`。
- [x] **舊配方不會被新偏好改寫。** dated edition 各自保存快照；`latest.json` 只作入口，過往日期檔保持原內容。
- [x] **手動手沖保持在範圍外。** 手動或 `historical` edition 不會出現公開配方按鈕。

## 靜態檢查

```powershell
node --check scripts/daily-brew.mjs
node --check api/edition-recipe.mjs
node --check server.mjs
node scripts/test-daily-recipe.mjs
node scripts/daily-brew.mjs --date 2026-08-22 --dry-run
```

## 本機操作檢查

1. 執行 `node server.mjs`。
2. 開啟 `http://localhost:4173/`。
3. 下一次自動日報生成後，「今日手沖」標題下方會出現「查看本期配方」。
4. 到「過往手沖」選擇相同日期，應看到同一個按鈕。
5. 打開後確認可看到晨報比例、模型、偏好、完整 Prompt、每次 attempt、搜尋規則與十篇來源。
6. 按「複製公開配方」，內容不可出現 API Key、帳號 ID、排除主題或私人網址。
7. 按「複製分享連結」，網址應指向 `/api/edition-recipe?date=YYYY-MM-DD`。
8. 選擇歷史模擬或手動手沖，確認不會出現配方按鈕。

2026-08-21 以前或功能上線前生成的舊檔若沒有 `generation_recipe`，介面不會補造不存在的 Prompt。從此版本開始的新自動日報才具備完整履歷。
