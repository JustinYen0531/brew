# 晨報主配方與來源櫃設計

> 狀態：產品方向已記錄，尚未進入介面與資料結構實作。
>
> 目的：固定「我的晨報配方」與「來源櫃」的責任，避免兩個功能再次重複。

## 核心分工

### 我的晨報配方

「我的晨報配方」決定一份報紙讀起來的樣子：今天關心什麼、由哪種編輯風格整理，以及內容怎麼排列。

使用者會在這裡選擇：

- 一份固定的科技／AI 主配方。
- 晨報的表達語氣。
- 晨報的編排與閱讀節奏。
- 閱讀難度、時間與篇數。
- 是否加入過往內容的複習。

### 來源櫃

「來源櫃」決定採編要去哪裡尋找材料：推薦網站、社群、指定網址與使用者自行加入的來源。

使用者會在這裡調整：

- 主配方預先推薦的來源。
- 各個來源的偏好程度。
- 指定社群、作者或網站。
- 新增自訂來源。
- 只能從指定網址尋找的硬性規則。
- 給採編室的額外備註。

大配方負責內容方向與閱讀感受；來源櫃負責材料從哪裡來。

## 第一版的五份固定主配方

第一版先集中在科技與 AI，並盡量讓初學者能找到適合自己的入口。使用者先選擇一份主配方，不開放完全自由的主題組合。

### 1. Vibe Coding 入門

內容包括：

- 使用 AI 寫程式。
- 與 Coding Agent 合作。
- 提示設計與上下文管理。
- 測試、驗證與除錯。
- 真實開發流程、失敗經驗與可重用方法。

適合想開始做網站、工具或小型產品，也希望逐漸理解程式開發方法的人。

### 2. AI 創作工作室

內容包括：

- AI 圖像與視覺創作。
- 動畫與影片生成。
- 音樂、聲音與配音工具。
- 不同創作工具的實際工作流程。
- 從靈感、生成、挑選到修改成品的方法。

重點放在真正完成作品的過程，不只介紹新模型或新功能。

### 3. AI 工作流與自動化

內容包括：

- Agent 與自動化流程。
- 資料整理與文件處理。
- 研究、摘要與知識管理。
- 個人與團隊的日常工作效率。
- 自動化的限制、檢查與失敗處理。

### 4. AI 產品與設計

內容包括：

- 從想法到原型。
- 介面與使用者體驗。
- AI 功能如何融入產品。
- 使用者回饋與產品修正。
- 發布、展示與取得第一批使用者的方法。

### 5. AI 工具與基礎素養

內容包括：

- 模型與工具如何選擇。
- Prompt 與 AI 協作基礎。
- 成本、隱私與安全。
- 常見誤解與使用限制。
- 如何判斷 AI 回答是否可靠。

這份主配方是剛進入 AI 世界的基礎入口。

## 每份主配方的固定內容

每份主配方需要預先定義：

- 名稱與一句簡介。
- 適合的讀者。
- 包含與排除的內容範圍。
- 初學者、普通與困難內容的建議比例。
- 大約十個預先整理的推薦來源。
- 預設的內容類型與生成規則。

各主配方可以共用部分高品質來源，但推薦清單與搜尋方向必須符合該配方。

## 咖啡師的編報風格

選完主配方後，使用者再決定希望由哪種風格的咖啡師整理晨報。這裡調整的是說明方式與閱讀感受，不調整來源。

### 表達語氣

- **陪你入門**：少用術語，多補背景與例子。
- **實作導向**：先講能做什麼，再提供步驟與注意事項。
- **編輯精選**：保留事件脈絡、編輯觀點與較完整的分析。

### 沖煮方式

- **濃縮快報**：篇幅短，快速掌握重點。
- **每日手沖**：摘要、例子與實作比例平衡。
- **慢萃專題**：篇數較少，每篇更深入。

一份完成設定的配方可以顯示為：

> AI 創作工作室  
> 實作導向 · 每日手沖 · 初學者友善

## 來源櫃的行為

進入來源櫃時，系統先依照目前主配方顯示約十個推薦來源。

使用者可以：

- 保留預設來源。
- 提高或降低某個來源出現的機會。
- 關閉某個來源。
- 搜尋並加入其他來源。
- 加入指定社群、作者或網址。
- 設定只能使用指定網址的硬性限制。

例如，選擇「Vibe Coding 入門」時，來源櫃可以提供 GitHub Discussions、Vibe Coding Taiwan、Hacker News 與相關開發者社群。選擇「AI 創作工作室」時，則換成圖像、影音、音樂工具與創作者社群。

「給採編室的備註」放在來源櫃底部，作為補充的語意要求。真正的來源限制與排序仍由欄位和規則控制，不只依賴 Prompt。

## 首次登入流程

第一次建立晨報時，只需要完成三步：

1. **今天想訂哪份報紙？**  
   從五份主配方中選擇一份。

2. **想由哪種咖啡師替你整理？**  
   選擇表達語氣與沖煮方式。

3. **每天想喝多少？**  
   選擇難度、5／10／20 分鐘、每天篇數，以及是否加入舊內容複習。

完成後直接進入自己的晨報首頁。來源櫃留給希望進一步調整的人，不在第一次登入時攤開所有來源與進階選項。

## 每一期需要保存的配方紀錄

每份生成完成的報紙都要保存當時真正使用的資料：

- 主配方。
- 表達語氣。
- 沖煮方式。
- 難度、閱讀時間與篇數。
- 使用的來源與來源限制。
- 額外備註。
- 實際生成 Prompt。
- 使用的模型與生成時間。

使用者之後修改自己的配方，不得改寫過往報紙的生成紀錄。

## 主配方選擇方式

目前保留三種產品做法：

1. **一次只選一份主配方（第一版建議）**  
   最容易理解，每份晨報的個性也最清楚。

2. **一份主配方，加一小份今日特調**  
   例如主要閱讀 Vibe Coding，偶爾加入 20% AI 創作。

3. **自由混合五份配方**  
   彈性最大，但容易讓第一次設定重新變成複雜的控制面板。

第一版建議採用「一次只選一份主配方」。等五份配方的來源與內容品質穩定後，再加入「今日特調」。

## 實作前仍需確認

- 第一版是否正式採用「一次只選一份主配方」。
- 五份主配方的名稱是否定稿。
- 每份主配方的十個初始來源，由誰負責審核與更新。
- 表達語氣與沖煮方式是否各保留三個選項。
- 現有「我的配方」頁面是否直接改成主配方總覽。
- 現有「配方細節」是否正式改名為「來源櫃」。

## 第一版完成後的使用者感受

使用者不必面對一大堆零散標籤。他先訂一份自己想看的科技報紙，再選擇喜歡的編輯風格。想仔細控制材料時，才走進來源櫃調整採編方向。

主配方回答：「今天想讀一份怎樣的報紙？」  
咖啡師風格回答：「希望它怎麼對我說話？」  
來源櫃回答：「這份報紙應該去哪裡找材料？」
